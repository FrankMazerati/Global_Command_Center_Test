# Maximus Optimus Command Center

IntelliStack Systems' enterprise operations workspace, built with React, TanStack Start, TypeScript, Vite, and Supabase.

> **Security posture:** Secured, Trusted & Compliant. UI visibility is never an authorization boundary; enforce access in server routes, RPCs, database policies, and storage policies.

## Development

Use the committed lockfile and the package manager declared in `package.json` (`pnpm`).

```bash
pnpm install --frozen-lockfile
pnpm dev
```

## Quality checks

```bash
pnpm build
pnpm lint
pnpm test
```

Run all three checks before requesting review. Confirm the Vercel framework, build command, and output directory match the actual build output; do not guess an output directory from an older deployment.

## Application architecture

- `src/lib/nav.ts` is the single source of truth for hamburger navigation taxonomy.
- `src/routes/` contains route definitions and page surfaces.
- `src/components/workspace/` contains focused workspace experiences.
- `src/lib/supabase.ts` owns the browser Supabase client configuration.
- `supabase/migrations/` contains versioned database changes.
- `supabase/seed/` contains explicitly labelled development/demo seed datasets.

The employee directory and profiles belong under **New Active Directory → Users and Identity**. Group objects and memberships belong under **New Active Directory → Groups and Organization**. Reuse the canonical identity model; do not build a second directory.

CEO, CFO, CIO, and CTO experiences are separate executive workspaces with role- and tenant-scoped data. Executive titles do not imply Global Admin / Super Admin access.

## Data provenance

Treat records generated by `company_history_seed_v1` and similar seed lineage as synthetic demo data. Do not present synthetic values as audited IntelliStack or Meta financial history. Meta's public financial disclosures must be imported from authoritative filings with period, currency, units, source, and accession lineage. Private Meta–IntelliStack commercial records must come from authorized source documents; otherwise they remain unavailable.

## Branch and release safety

Work on feature branches and review diffs before merging. Never apply production database migrations or alter live role/RLS policy without a reviewed migration, recovery plan, and successful positive and negative authorization tests. A preview deployment is not production certification.
